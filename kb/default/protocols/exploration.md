# 探索模式协议

## 适用场景

- 用户提出开放性问题（"告诉我关于X的一切"）
- 需要理解一个新领域的概念结构
- 寻找概念之间未被意识到的隐含关联
- 从一个已知概念出发，发现系统中有哪些相关概念

## 核心策略

**沿 `enables` 边广度优先展开。**

探索不是深入一个方向，而是从起点辐射，发现可达的概念子图。enables 边是优先路径——它标记"理解A有助于理解B"的关系，正是探索者需要的导航。

## 执行流程

### 第一步：识别起点

1. 解析用户输入中的关键词
2. 对照 MANIFEST.md 的 triggers 列，匹配触发关键词
3. 声明初始激活概念 ID 列表

```
[探索] 识别触发关键词：{关键词列表}
[探索] 初始激活：{概念ID列表}
```

### 第二步：加载初始子图

1. 加载初始概念文件的完整内容（molecule）
2. 读取每个概念的 edges 字段
3. 标记所有 `enables` 边指向的下游概念

```
[探索] 已加载：{已加载概念列表}
[探索] 发现 enables 边 → {下游概念列表}
```

### 第三步：广度优先展开

1. 从已加载概念的 `enables` 边出发，逐层扩展
2. 每扩展一层，加载新概念的 atom（从 MANIFEST）或 molecule（如果需要深入）
3. 当满足以下任一条件时停止扩展：
   - 所有 `enables` 边指向的概念都已加载
   - 激活子图达到上下文预算（建议 ≤ 5 个概念的完整 molecule）
   - 用户中断并改变方向

```
[探索] 第 {N} 跳展开 → 新增：{概念列表}
[探索] 当前激活子图：{所有已加载概念}
```

### 第四步：构建理解

1. 在激活子图内综合推理
2. 识别子图中的 `contradicts` 边——探索中发现张力是最有价值的发现
3. 如发现边指向未加载概念，声明需要扩展激活

```
[探索] 发现张力：{概念A} ↔ {概念B}（{边类型}）
[探索] 建议深入：{未加载概念ID}（理由：{为什么值得探索}）
```

### 第五步：写回发现

如果探索中发现新的概念关联或张力：

1. `propose-edge`：向 `proposals/edges/` 写入新边提案
2. `flag-tension`：向 `frontier.md` 添加新发现的张力

## 加载优先级

当上下文预算有限时，按以下优先级决定加载哪些概念的完整 molecule：

| 优先级 | 条件 | 原因 |
|--------|------|------|
| P0 | 起点概念 | 用户直接关注的入口 |
| P1 | `enables` 边的 1-hop 邻居 | 直接支撑理解起点 |
| P2 | `depends-on` 边的邻居 | 起点概念依赖的前置知识 |
| P3 | `contradicts` 边的邻居 | 揭示张力的对立面 |
| P4 | `analogous-to` 边的邻居 | 跨域类比，最低优先 |

## 输出格式

探索结果应包含：

```
## 探索报告：{起点概念}

### 激活子图
{列出所有已加载概念及其层级}

### 核心发现
{在子图内综合推理得出的结论}

### 张力识别
{发现的 contradicts 边和潜在矛盾}

### 未展开节点
{已识别但未深入的 enables 边目标，建议后续探索方向}
```

## 注意事项

- 探索模式 **不追求完整性**，而是追求 **发现性**——让用户看到他没想到的关联
- 不要一次性加载过多概念——5 个完整 molecule 是合理预算
- 遇到 `contradicts` 边必须主动报告，不要忽略张力
- 如果某个 `enables` 边指向的概念不在 MANIFEST 中（L2/L3 未写入），说明这是 frontier 上的待展开节点
