# 生成模式协议

## 适用场景

- 用户需要创造新概念或新方案（"如何设计X？"）
- 从公理出发推演特定语境下的具体化方案
- 将抽象原则落地为具体实践
- 在张力中寻找第三条路

## 核心策略

**从 L0 公理出发，沿 `instantiates` 链向下推演，在约束中创造。**

生成不是从零开始发明——它是在公理框架内，根据语境和约束，推演出具体化的方案。公理是不可违反的底线，约束是创造的空间，语境决定哪些推演路径成立。

## 执行流程

### 第一步：锚定公理

1. 识别生成任务涉及的核心价值（从 L0 `value` 出发）
2. 确认相关主体（从 L0 `agent` 出发）
3. 界定生效语境（从 L0 `context` 出发）
4. 识别核心张力（从 L0 `tension` 出发）

```
[生成] 公理锚定：
  - 主体：{涉及的 agent}
  - 价值：{要追求的 value}
  - 语境：{生效的 context}
  - 张力：{要处理的 tension}
```

### 第二步：展开 L1 框架

1. 从公理出发，激活相关的 L1 核心概念
2. 在 L1 层建立推理框架：
   - 目标（goal）：在这个语境下，主体要达到什么状态？
   - 需求（need）：什么是不可妥协的底线？
   - 约束（constraint）：行动空间被什么限制？
   - 张力映射到决策（decision）：什么选择需要做出？
   - 风险（risk）：什么可能破坏目标？

```
[生成] L1 框架：
  - 目标：{...}
  - 需求：{...}
  - 约束：{...}
  - 决策点：{...}
  - 风险：{...}
```

### 第三步：向下推演

1. 沿 `instantiates` 链向下：从 L1 核心概念推演出 L2/L3 具体化
2. 每个推演步骤必须标注：
   - 依据哪条公理或核心概念
   - 在什么语境条件下成立
   - 推演的置信度（confirmed / hypothetical / contested）

```
[生成] 推演步骤 1：
  - 从 {L1概念} 出发
  - 语境条件：{...}
  - 推演结果：{L2/L3 具体化}
  - 置信度：{confirmed / hypothetical / contested}
```

### 第四步：张力中创造

当推演遇到张力（两个价值在约束下无法同时满足）时：

1. **不要消除张力的一端**——张力是真实的，消除等于回避
2. **寻找重新框架**——引入新概念，使原来矛盾的两个价值在同一更高层次框架下兼容
3. **设计权衡机制**——如果无法消解，设计在什么语境下优先哪个价值
4. **保留可逆性**——如果决策不可逆，优先选择保留未来调整空间的方案

```
[生成] 张力处理：{张力描述}
  - 路径A（传统取舍）：{...} → 置信度：{...}
  - 路径B（重新框架）：{...} → 置信度：{...}
  - 推荐：{路径A/B}，理由：{...}
```

### 第五步：验证推演

对生成的方案执行轻量验证：

1. 回溯检查：方案是否违反任何 L0 公理？
2. 矛盾检查：方案内部是否存在未解决的矛盾？
3. 边界检查：方案在什么语境下会失效？

```
[生成] 自验证：
  - 公理一致性：{通过/失败}（{具体检查}）
  - 内部矛盾：{有/无}（{具体矛盾}）
  - 失效语境：{...}
```

### 第六步：写回贡献

1. 如果推演产生了新概念 → 建议写入对应层级的概念文件
2. 如果发现了新的边关系 → `propose-edge` 写入 `proposals/edges/`
3. 如果推演暴露了新的张力 → `flag-tension` 写入 `frontier.md`
4. 如果 atom 描述需要更新 → `refine-atom` 写入 `proposals/atoms/`

## 输出格式

```
## 生成报告：{任务描述}

### 公理锚定
{主体、价值、语境、张力}

### 推演链
{每步推演的从→到、语境条件、置信度}

### 方案
{最终生成的方案/概念/设计}

### 张力处理
{遇到的张力和处理方式}

### 自验证结果
{公理一致性、内部矛盾、失效语境}

### 新增贡献
{建议写入的新概念/新边/新张力}
```

## 注意事项

- 生成模式 **不可违反 L0 公理**——任何违反公理的推演结果都是无效的
- hypothetical 的推演可以作为探索方向，但不能作为决策基础
- 生成不是发明——是在公理框架内的演绎。如果发现需要违反公理才能生成，说明公理本身需要重新审视（这应作为 flag-tension 写回）
- 在张力中寻找第三条路是生成模式的最高价值——简单的取舍不需要生成模式，探索模式就够
- 生成的方案必须附带自验证——没有验证的生成是不可信的
