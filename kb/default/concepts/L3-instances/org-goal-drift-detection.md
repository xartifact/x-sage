# 组织目标漂移检测机制 Org Goal Drift Detection

## 核心内容（molecule）

组织目标漂移检测是一套季度执行的"起源检查"仪式，用于在组织层面系统性检测和修正目标漂移。它基于一个简单的前提：组织比个人更容易漂移，因为反馈回路更长、更弱。如果不建立定期的漂移检测机制，团队会不知不觉地从"为什么做"滑向"在做什么"。

### 季度起源检查仪式

**频率**：每季度一次，集中半日（3-4小时）。

**参与者**：目标相关团队全员 + 一到两位"见证人"（不直接参与该目标的其他团队代表）。

**流程**：

1. **重启档案（30min）**：回顾季度初写下"我们为什么做这件事"的回答。
2. **漂移回溯（60min）**：对照5项信号清单逐一检查。每项信号等级评分：0（无漂移）到3（严重漂移）。
3. **根源对话（45min）**：对得分≥2的信号，追溯漂移根源。追问："我们在什么时候从'为了Y而做X'变成了'为了做X而做X'？"
4. **干预决策（30min）**：选择一种干预模式并指定执行人。
5. **目标重新锚定（15min）**：更新目标陈述，写下本季度的"我们为什么做这件事"作为下一季度检查的基准。

### 5项漂移信号清单

| 编号 | 信号 | 检测方法 | 评分标准 |
|------|------|---------|---------|
| 1 | **指标替代** | 团队讨论中，KPI 名词出现频率是否超过目标名词？例如讨论"DAU怎么涨"多于"用户体验怎么提升" | 0=经常谈目标 / 1=二者均衡 / 2=大多数谈指标 / 3=只谈指标不谈目标 |
| 2 | **工具自恋** | 周会/复盘的时间分配——讨论工具、流程、方法的时间是否超过了讨论问题和成果的时间？ | 0=工具为问题服务 / 1=少量工具讨论 / 2=工具讨论占优 / 3="工具分享"是会议的主要议程 |
| 3 | **动作惯性** | 回答"这个季度最重要的事是什么"——答案如果是"继续做X"而非"完成Y"，说明动作已取代目标。 | 0=结果导向的答案 / 1=模糊 / 2=明确的"继续做" / 3=无人能说出季度目标 |
| 4 | **解决方案锁定** | 面对新问题时的第一反应：是否总是回到熟悉的方案模式？"我们擅长微服务，所以所有新需求都用微服务解决" | 0=方案匹配问题 / 1=偶尔默认方案 / 2=经常方案先行 / 3=方案比问题定义更重要 |
| 5 | **语境失效** | 原始目标成立时的语境参数（用户、市场、技术）是否已变，但目标未做相应调整？ | 0=语境持续评估 / 1=少量过时 / 2=明显语境改变但目标未动 / 3=语境已完全不相关 |

### 3种干预模式

**模式一：重新锚定（适用于轻度漂移，信号评分总和 ≤5）**

- 停止一切"做但不问为什么"的活动
- 用半日重新撰写目标陈述，确保团队每个人都能用一句话说清"我们为什么要做"
- 建立"周目标回顾"——每周一花15分钟集体回答"这周的工作服务于哪个原始目标？"

**模式二：修剪分支（适用于中度漂移，信号评分总和 6-10）**

- 列出团队当前的所有活动和项目
- 为每个活动标注"直接服务于目标"、"间接服务于目标"、"与目标无关"
- 强制停止所有"与目标无关"的活动，即使它们看起来"很有价值"
- 对"间接服务"的活动设定转化时间表——要么在一个月内变为直接服务，要么停止

**模式三：死亡重启（适用于严重漂移，信号评分总和 ≥11，或单信号为3分）**

- 完全暂停该目标的所有执行活动
- 用一周重新做"目标发现"——如同从未做过这件事一样，从零开始回答"当前最重要的价值缺口是什么"
- 允许结论为"停止这个目标"——如果重新发现的结果显示原始目标已不再重要
- 如果重新锚定后三个月仍然漂移，永久关闭该目标

## 张力与开放问题

- **检查成本**：半天的季度检查对于高速团队可能是沉重负担。当节奏紧张时，检查仪式往往被跳过——而跳过检查恰恰是漂移加速的信号。如何降低检查的摩擦？
- **见证人的独立性**：长期合作的团队中，见证人可能失去客观性。轮换见证人或引入外部视角是否必要？
- **诊断 vs. 执行**：检测到漂移是一回事，执行干预是另一回事。模式三（死亡重启）需要组织权力支持——没有决策权的团队即使检测到严重漂移也可能无法行动。
