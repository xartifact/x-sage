# 约束传导链映射 Constraint Cascade Map

## 核心内容（molecule）

约束传导链映射是一种从下游症状向上游根源追溯约束传导路径的技术。它基于一个关键洞察：下游团队感知到的约束几乎总是上游约束的传导结果——不追溯传导链，任何局部解决方案都是治标不治本。映射技术让隐性的传导链变得可见、可分析、可干预。

### 映射方法：五步追溯法

**第一步：症状定位** — 找到最下层的可见症状。

团队在哪个层面感受到了"不舒服"？通常表现为：用户满意度下降、交付延期、质量下降、士气低落。记录症状，不要急于定义约束。

**第二步：逐层追问"什么约束了这里"**

从症状出发，逐层向上游追问。每层回答一个问题："当前节点的什么条件限制了结果？这个条件从哪里来？"

用表格追溯：

| 层级 | 可见现象 | 背后约束 | 上游来源 |
|------|---------|---------|---------|
| L1（症状层） | 用户满意度下降 | 功能交付速度跟不上需求 | ??? |
| L2 | 开发速度慢 | 团队同时在维护三个版本 | ??? |
| L3 | 版本维护负担大 | 架构耦合导致无法独立迭代 | ??? |
| L4（根源层） | 架构耦合 | 早期为了快速上线采用了大单体架构 | 原始时间约束 |

**第三步：标注传导关系**

为每个传导步骤标注关系类型：直接传导（A→B，无中间层）、放大传导（A→B++, 约束在传导中放大）、衰减传导（A→B-, 约束在传导中减弱）。

**第四步：寻找中断点**

在传导链上标注可中断的节点。中断成本 = 在该节点切断约束传导所需的资源。越靠近上游，中断成本越低但执行难度越大。

**第五步：生成干预方案**

基于中断点生成三种方案：源头切断（修改上游约束）、路径阻隔（在传导链中加入缓冲）、下游适应（修改下游的预期或流程）。

### 真实案例：预算削减的传导链

**场景**：某SaaS公司因营收未达标，CTO决定削减20%基础设施预算。

**传导链映射**：

```
L5（根源）：营收未达标 → 公司现金流约束
  │
  └→ L4（资源决策）：削减20%基础设施预算
       │ 传导类型：直接传导（强制）
       │
       └→ L3（运营约束）：团队规模缩减，无法同时维护多环境
            │ 传导类型：放大（20%预算削减 → 40%维护能力下降，
            │          因为固定成本不随预算线性减少）
            │
            └→ L2（交付约束）：只能维护生产环境，测试环境降级
                 │ 传导类型：衰减（部分影响被团队加班吸收）
                 │
                 └→ L1（质量约束）：合并前缺少预发布验证
                      │ 传导类型：放大（跳过测试 → 线上故障率上升）
                      │
                      └→ L0（用户体验约束）：线上故障增加 → 用户满意度下降
                           │ 最终后果：用户流失 → 营收进一步下降
                           │           → 现金流约束加剧（恶性循环）
                           └→ 回到L5，形成正反馈
```

**关键发现**：在这个传导链中，有两个放大节点（L3→L2，L1→L0）和一个衰减节点（L2→L1）。L4→L3的放大效应被团队加班（衰减）部分抵消，但代价是团队不可持续。

**潜在中断点**：

| 中断点 | 方法 | 成本 | 难度 |
|--------|------|------|------|
| L5源头 | 补充融资或调整营收目标 | 高（外部不可控） | 极高 |
| L4决策 | 砍功能而非砍基础设施预算 | 中（需产品决策） | 中 |
| L3→L2路径 | 引入自动化测试替代多环境 | 中（前期投入） | 中 |
| L2→L1衰减 | 正式接受质量下降的短期风险 | 低（但需团队认同） | 低 |

### 实操工具

约束传导链可以用简洁的线性符号记录：

```
营收未达标 → [现金流] → 预算削减20% → [团队: 40%维护力下降]
  → 测试环境降级 → [缺陷率: 2x] → 用户满意度-15%
```

箭头 `→` 表示传导方向，方括号 `[ ]` 表示约束的量化指标。

## 张力与开放问题

- **映射深度 vs. 行动能力**：越深的传导链分析越接近真相，但也越触及组织不可控因素（如公司战略、市场环境）。知道根源但无法改变是否比不知道更痛苦？
- **多根传导链**：实际项目中，一个症状往往是多条传导链的交汇点。用户满意度下降可能同时源于资源配置、产品方向、技术支持三条链。如何合并和优先级排序多链分析？
- **传导链的时效性**：传导链不是静态的——系统架构变化后会形成新的传导路径。映射需要定期更新，但重新映射的成本如何控制？
