# 决策可追溯性 Decision Traceability

## 核心内容（molecule）

决策可追溯性是保留决策的推理结构以供回溯学习的能力。它使决策可以被解释——不是"当时选了A"而是"当时为什么选了A"。可追溯的决策可以从经验中学习，不可追溯的决策只能看结果赌运气。

### 从 L1 推导

- **decision**：可追溯性是决策质量的元属性——好决策可能产生坏结果（因为语境不可预测），但可追溯的决策无论结果如何都能产生学习价值。
- **agent**：可追溯性必须归属到做出决策的主体——"谁在什么语境下为什么选择了A"。主体信息使得未来在类似语境下的决策者可以参考前人经验。
- **context**：可追溯性的核心是记录语境——因为同一个决策在不同语境下的正确性不同。只记录"选了A"而不记录语境，回溯时无法判断A在当前语境下是否仍然合理。

### 核心属性

1. **语境快照**：可追溯的决策必须包含决策时的语境快照——当时已知什么、未知什么、约束是什么、目标是什么。语境变化后，原始决策可能不再最优，但推理结构仍然有参考价值。
2. **替代方案记录**：不只记录选择了什么，还要记录放弃了什么以及为什么放弃。替代方案是未来重新评估决策时的起点——如果语境变化，之前放弃的方案可能变得可行。
3. **决策质量 vs 结果质量分离**：可追溯性使得"决策质量"和"结果质量"可以被分离评估。好决策+坏结果 = 需要改进信息收集或应对不确定性；坏决策+好结果 = 运气，不应被强化。

### 记录格式（ADR 简化版）

```markdown
## 决策：{标题}
- **决策者**：{主体}
- **日期**：{时间}
- **语境**：{当前环境、已知信息、约束}
- **目标**：{要达到什么状态}
- **选项**：
  - A：{描述} → 优点：{} 缺点：{}
  - B：{描述} → 优点：{} 缺点：{}
- **选择**：{A/B} → 理由：{}
- **不确定性**：{哪些信息当时不可知}
```

## 张力与开放问题

- **追溯成本**：记录决策推理结构需要时间和认知投入。在时间压力下，"先做再记"往往变成"做了不记"。如何降低追溯成本？
- **追溯的政治性**：决策记录可能被用于追责——这导致记录者有动机美化推理过程。如何建立"学习而非追责"的追溯文化？
- **隐性决策**：很多决策从未被显式做出——它们是默认选项、不行动的选择、延迟的决定。这些"隐性决策"往往比显式决策影响更大，但最不可追溯。
