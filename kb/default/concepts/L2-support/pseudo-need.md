# 伪需求 Pseudo Need

## 核心内容（molecule）

伪需求是用户表达的解决方案而非真实需求。当用户说"我需要搜索功能"时，真实需求可能是"我需要快速找到信息"——搜索只是众多可能的解决方案之一。伪需求将"如何做"误认为"要什么"，是最常见的需求识别谬误。

### 从 L1 推导

- **need**：伪需求是需求的表观形式——它看起来像需求（主体表达为"我需要X"），但X是解决方案而非需求本身。两者的区别在于：需求描述的是价值和缺口，伪需求描述的是具体的实现方式。
- **agent**：伪需求归属于主体——但主体往往不知道自己表达的是伪需求。这不是欺骗，而是认知局限：人们习惯用已知的解决方案来描述未知的需求。
- **context**：伪需求在特定语境下可能就是真实需求——如果语境限定了唯一可行的解决方案，那么"我需要X"既是解决方案也是需求。关键在于语境是否允许其他解决方案。

### 核心属性

1. **解决方案伪装**：伪需求的核心特征是——它隐含了一个未被验证的假设："X是满足需求的最佳/唯一方式"。揭开这层伪装的方法是追问"为什么需要X"，直到答案不再是"因为Y更好"而是"Y本身重要"。
2. **路径锁定**：如果伪需求被当作真实需求执行，它会导致路径锁定——团队开始构建搜索功能，而不是探索"快速找到信息"的所有可能方案。路径锁定使得后期修正代价极高。
3. **可转化性**：伪需求不是"错误"——它是通往真实需求的线索。每个伪需求背后都有一个真实需求，关键是从解决方案往回追溯而非否定用户表达。

### 识别方法

| 用户说 | 真实需求可能在 | 追问方向 |
|--------|--------------|---------|
| "我需要搜索" | 快速找到信息 | "你在找什么？找不到时会发生什么？" |
| "我需要更多按钮" | 对操作的控制感 | "你想控制什么？当前哪里让你失控？" |
| "我需要导出功能" | 在其他场景使用数据 | "导出后你做什么？为什么不能在这里完成？" |
| "我需要更快的系统" | 减少等待的挫败感 | "等的时候你在做什么？等多久开始烦躁？" |

## 张力与开放问题

- 与 `need` 的 contradicts 关系：伪需求是对需求的"覆盖"——它以解决方案的形式遮挡了真实需求，使得需求分析误入歧途。
- **专家伪需求**：不只是用户会产生伪需求——专家（架构师、设计师）也会用技术方案伪装需求。"我们需要微服务架构"可能是伪需求，真实需求是"系统需要独立扩展"。
- **伪需求的灰色地带**：有些表达介于需求和解决方案之间——"我需要实时协作"既描述了价值（协作）也限定了方式（实时）。如何处理这种混合表达？
