# 约束传导链 Constraint Cascade

## 核心内容（molecule）

约束传导链描述一个层面的约束沿依赖链传导到下游的现象。上游的约束不是独立存在的——它会沿着系统内的依赖关系传播，使得低层约束比表面看到的更严苛。忽视传导链会导致局部优化而全局恶化。

### 从 L1 推导

- **constraint**：约束传导链是约束在系统中的传播形式——单个约束本身的影响有限，但当它沿依赖链传导时，影响范围和严重程度都会放大。
- **context**：传导链的长度和强度取决于语境——在紧耦合系统中传导快且强，在松耦合系统中传导慢且弱。系统架构决定了传导特性。
- **tension**：约束传导经常在下游制造新的张力——上游的技术约束传导为产品约束，产品约束传导为用户体验约束，每一层传导都可能产生新的价值冲突。

### 核心属性

1. **放大效应**：约束在传导过程中往往会放大——一个5%的时间约束传导到下游可能变成15%的交付约束，因为每一层都有自身的缓冲消耗。
2. **隐性传导**：传导往往是不显性的——下游感知到约束但不知道它来自哪里。团队觉得"为什么总是不够时间"，但根源在上游的资源分配约束。不追溯传导链就无法解决根本问题。
3. **可中断性**：传导链可以在某些节点被中断——通过引入缓冲、替代方案或重新设计依赖关系。中断传导链的成本取决于中断点的位置——越靠近源头，中断成本越低但难度越大。

### 典型传导链

| 上游约束 | 传导路径 | 下游影响 |
|---------|---------|---------|
| 技术债务 | 技术约束 → 开发速度 → 交付周期 → 用户满意度 | 用户流失 |
| 预算限制 | 资源约束 → 团队规模 → 功能覆盖 → 产品竞争力 | 市场份额下降 |
| 合规要求 | 法律约束 → 数据处理 → 架构选择 → 开发成本 | 创新受限 |
| 时间压力 | 进度约束 → 代码质量 → 维护成本 → 新功能速度 | 技术债务循环 |

## 张力与开放问题

- **传导 vs 因果**：约束传导和因果关系的区别是什么？传导是因果的一种——但不是所有因果都是约束传导。传导特指"限制性条件沿依赖链传播"。
- **正反馈环路**：当约束传导形成闭环时（如"技术债务→开发慢→时间紧→更多技术债务"），系统进入正反馈恶化。如何检测和打破这种环路？
- **传导链的可视化**：当前系统只在概念层面记录约束，不记录约束在具体项目中的传导链。如何让传导链成为显式知识？
