# ADR-001 — 自研 sage-db 的存储与语义边界

- 状态：自研方向已由用户确认；下述是本轮设计修订，待实现与验收。
- 日期：2026-11-16。
- 范围：Rust 自研完整知识图数据库；替换现有 Markdown/结构化存储运行时。
- 正式名称：sage-db；沿用 sage 命名，由 x-sage 承载上层知识库产品。
- 本文接续 ADR-001 旧草案，格式尚未冻结，不能将修订当成已发布兼容承诺。

## 1. 背景与约束

用户明确拒绝保留 SQLite，要求直接优化自研数据库。运行时、持久后端和测试 oracle
均采用自研方案；旧服务只负责一次性导出中立迁移材料。

当前问题跨越存储、语义与审阅：移植原代码并不会自动修复重导覆盖、基线对象错配、
证据悬空或最宽路径。新设计必须把这些反例写进不可跳过的验收门。
设计分册入口：[system.md](system.md)。

## 2. 决策

### D1 — 完整事件历史与内容 blob 是权威

日志覆盖全部知识/提案/会话元数据；大内容保存为不可变、内容寻址 blobs。
Fact、索引、记录 checkpoint 和缓存可重建。删除缓存不损失知识，丢失 blob 则是
权威损坏，不能笼统声称“所有数据都能从边日志重建”。

### D2 — 断言身份与语义层级保留

每条 Assertion 独立存在，撤回按身份操作。可推导不等于可以自动删除作者断言。
layer 是持久语义分类；definition_depth 是拓扑派生值；目录是导出投影。
这保留现有 L2 草案和 L3→L1 实例的意义，移除旧草案“图深度等于层级”的假设。

### D3 — 固定规则、四元素注解载体

使用 bottom + contested/hypothetical/confirmed 的 max/min；存在性与争议分开。
规则配置版本化，formal-v1 的定义蕴含与更严校验属于显式规则迁移。
不援引 Armstrong 增广律证明跨关系复合被禁止。

### D4 — 不可变事务段、CURRENT 原子发布、只提供 durable ACK

写依赖文件并同步 → 发布 manifest 并同步 → 替换 CURRENT 并同步目录 →
发布内存快照 → ACK。未知提交结果按持久 request_id 恢复，不猜测成功或失败。
v1 不支持提前 ACK 的 batch/none。以后 group commit 可以优化刷盘次数，不降低保证。

### D5 — 单提交者、有界快照与按需推理

每 KB 串行写入并持有 OS 目录锁；读者用不可变版本。
提交只需要记录/图约束校验与基础索引，不等待全量闭包。
按需单源缓存以 graph_digest/rules_digest/engine_version 等键隔离；支持精确查询预算拒绝。
所有快照、在飞请求、候选与缓存都计入全局内存账本。

### D6 — 持久提案与事务缓冲分离

提案提交成功即持久，但不进入活动事实。批准和内容变更同事务。
请求只操作自己的完整 TxEnvelope；不能共享匿名 pending set。
幂等 outcome 同事务落盘，重启后仍能识别已成功的请求。

## 3. 简化与明确延期

| 事项 | v1 决策 | 理由 |
|---|---|---|
| SQLite 后端 / oracle | 不采用 | 用户明确选择自研；参考求值器用独立 Rust 集合算法 |
| DRed、增量删除 | 延期 | 先让新快照按需重算；没有必要把复杂删除索引放入提交正确性路径 |
| 全量闭包物化 | 不做 | 长链的闭包平方增长，按需缓存更容易约束资源 |
| 任意 DSL / 通用 IR | 延期 | 固定动词与计划能覆盖当前工作流 |
| HA、多写者、跨 KB 推理 | 延期 | 尚无共识、命名空间和跨域授权契约 |
| 分页游标 | 延期 | 先用有界结果和明确 completion，避免新增会话状态 |
| 历史日志截断 | 延期 | v1 保留已提交历史与引用 blobs，先验证备份和恢复 |
| 向量 ANN | 延期 | 精确扫描作为可验证基线，超预算明确拒绝 |

这些取舍不是宣称其他数据库或语言“无法表达”这些语义，
而是限定本项目自研 v1 必须承担的范围。

## 4. 对旧草案的修订追踪

| 旧主张 | 修订 | 对应分册 |
|---|---|---|
| 只有二元 Assertion 是真源 | 所有记录事件 + blobs，保留完整产品能力 | data-model / storage |
| layer 不存、按定义边推出 | layer 单一权威 + definition_depth 派生 | data-model |
| 94 条自动归约为 58 条 | 保留每条来源，禁止自动删断言 | axiomatics |
| 每次提交等全闭包 | 直接图校验后提交，查询按需推导 | inference |
| batch(64) 默认、仍逐次 fsync | v1 只 durable；未来批量只合并等待 | storage |
| 日志不截断但 GC 未保留历史 | 全部已提交日志/历史 blobs 不进入 v1 GC | storage |
| 仅 via 指针即可解释所有规则 | 带规则与 Assertion 修订的有界证明 | inference |
| Header 提前知道截断 | Footer 承担完成状态，断流不可当完整 | query-dsl |
| 提案等于内存 pending | 提案持久化，事务按请求隔离 | server |
| SQLite oracle 不可跳过 | 独立参考求值器 + 事件重放模型 + 故障注入 | system |

## 5. 代价与验收承诺

自研需要承担崩溃恢复、格式升级、备份和损坏检测；不能用预计代码行数证明可控。
v1 保留历史会消耗磁盘；保留快照会消耗内存；两者以配额拒绝新负载，而非偷偷删数据。

确认方向不等于宣称已经达成性能目标。P0/P1 先建立基准与故障注入，
P5 完成全对象迁移验证后才允许实际切换。所有阶段与退出条件见 system。
