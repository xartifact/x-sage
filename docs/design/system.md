# 系统设计 — 自研知识图数据库 sage-db

> 状态：P0（types/infer/reference）已通过验收；P1（存储）处于 P1-1 契约阶段，
> 尚无运行时实现。2026-11-16 用户确认采用自研数据库方向。
> 设计修订不代表磁盘格式已经冻结（format major 0）或运行时已经切换。

sage-db 是 Rust 实现的单节点、带来源追踪的专用知识图数据库。事务日志、记录存储、
版本快照、恢复和查询执行均由项目实现；运行时与测试 oracle 均不依赖 SQLite。
自研范围包括完整知识记录，不能只替换图边而丢失正文、证据和审阅历史。

正式名称为 `sage-db`，延续 sage 产品命名。`x-sage` 是上层知识库产品，
`sage-db` 是其自研数据库；Rust crate 统一使用 `sage-db-*` 前缀。

## 2. 产品边界与取舍

| 维度 | v1 决定 |
|---|---|
| 权威 | 已提交的类型化事件日志 + 内容寻址 blobs；其余索引可重建 |
| 数据 | 概念、关系断言、文本 claim、证据、资产、向量、提案、会话状态 |
| 并发 | 每 KB 一个提交者；所有写事务串行应用；读请求钉住不可变版本 |
| 计算 | 固定规则模板、版本化关系模式；不开放用户规则语言 |
| 内存 | 有配额的常驻基础图；正文、资产、向量按引用读取；闭包按需计算 |
| 持久性 | v1 仅 durable 提交：fsync 完成且快照发布后才 ACK |
| 部署 | 单进程多 KB；不支持多进程共同写库、跨 KB 事务、HA 或在线副本 |
| 查询 | 类型化动词；v1 不实现 SQL、通用 join、分页游标 |

使用成熟的压缩、哈希、网络和序列化库不改变自研存储的决定。
不自写密码学，也不把格式兼容承诺替换成“永远不得升级”。

## 3. 模块边界

依赖方向按表约束；纯推理层不能依赖持久化内核。

| crate | 职责 | 允许依赖 |
|---|---|---|
| sage-db-types | 身份、记录、事件、版本、结果类型，无 I/O | 通用类型库 |
| sage-db-format | 显式字节编解码、校验和、格式版本，无文件 I/O | types |
| sage-db-infer | 基础图校验、最宽路径、证明生成，无磁盘/网络 I/O | types |
| sage-db-store | 文件、fsync、CURRENT、恢复、GC | types、format |
| sage-db-kernel | 提案应用、串行提交、快照发布、资源账本 | types、infer、store |
| sage-db-query | 固定查询计划、排序、搜索融合 | types、infer、只读 SnapshotView |
| sage-db-server / sage-db-cli | 认证、协议、管理 / 纯远程客户端 | kernel、query / 协议类型 |

SnapshotView 定义在 types：提供记录与基础邻接的只读访问，不能把无预算的
fact()/explain() 藏进访问器。闭包与证明是 query/infer 的显式有界操作。
Writer 接受完整 TxEnvelope，不持有一个可被不同客户端混用的全局 pending set。

## 4. 必须保持的不变量

| ID | 不变量 | 负责模块 |
|---|---|---|
| I1 | 已 ACK 的事务在声明的文件系统故障模型下可恢复；提交不含部分操作 | store |
| I2 | CURRENT 是唯一提交根；不能扫描最高编号文件猜测提交是否发生 | store |
| I3 | 权威损坏明确报错；不能自动回退旧 Markdown 或旧版本冒充 latest | kernel |
| I4 | metadata 可从已提交日志恢复；内容字节由日志引用的 blobs 保存 | store |
| I5 | 断言保留独立身份、修订和审计；派生冗余不构成删除理由 | kernel |
| I6 | 同一读请求只有一个版本；旧缓存不得绑定到不同 graph_digest/rules_digest/engine_version | query |
| I7 | 引用只能指向同库的已存在记录；TermCreate 的 subject 是将创建的预留键；退役保持历史可追溯 | kernel |
| I8 | 新增支撑时置信度只升不降；撤回允许降级或消失 | infer |
| I9 | unknown（无结果）、absent、contested 与输出截断在结果中可区分 | query |
| I10 | 预算在分配和展开过程中执行；不能先 OOM 再检查上限 | 全部 |
| I11 | 审阅基线覆盖实际写入/读取集合；版本未变不能替代审阅授权 | kernel |
| I12 | pending 提案持久化但不进入事实；事务缓冲与提案分离 | kernel |
| I13 | pending 提案陈旧不得阻塞无关提交；只有被批准的那笔事务检查自己的读写集合 | kernel |
| I14 | COMMIT_UNKNOWN 未解除前该 KB 只读；看到新根不是提交成功的证明 | store |
| I15 | 历史修订可按 (record, revision) 定位，不依赖在线整库快照窗口 | store |
| I16 | 两个求值器在规范化事实上一致；证明各自独立构造并回放核验 | infer / reference |
| I17 | 中断（预算/证明/取消/deadline）不是结果：返回类型化错误，不返回部分行 | infer / reference |
| I18 | 规则 profile 与 rules_digest 随图与请求传递；仅有 digest 不足以选择语义 | types / kernel |
| I19 | 字段的“出现 / 值可缺省 / 兼容性”是三个独立轴；未知必需语义一律拒绝，advisory 也必须原样保留字节 | format |
| I20 | 摘要依赖无环：任何摘要都不直接或间接覆盖自身；首次持久结果只含准备期可确定的字段 | format / store |
| I21 | 规则配置是带规范字节的数据：加载时由 `rules_ref` 重算 `rules_digest`，只比对编译期常量不合格 | format / store |
| I22 | 每个登记记录事件携带完整 after-image；仅记录图边不能满足全记录恢复承诺 | format / store |

## 5. 分阶段施工与退出条件

每阶段交付可执行验证，不以预计代码行数衡量完成。

| 阶段 | 交付 | 退出条件 |
|---|---|---|
| P0 语义 | types、infer、朴素参考求值器 | 随机小图与优化求值按规范化事实行逐项一致；置信度提升/撤回/对称/证明独立回放通过；最强、最短与稳定平局分别验证 |
| P1 存储 | format、事务日志、CURRENT、基础恢复 | 每个写入/fsync/rename 点故障注入；ACK 不丢、事务不拆、重试不重复；COMMIT_UNKNOWN 解除流程通过 |
| P2 记录 | 全记录生命周期、提案、CAS、blobs | 审阅与知识变更同事务；引用无悬空；重启保留 pending；陈旧 pending 提案不阻塞无关提交 |
| P3 查询 | 基础索引、有界查询、缓存、搜索 | 深链/密 DAG 不触发全闭包 OOM；缓存命中与未命中结果一致；历史修订窗口外仍可按修订读取 |
| P4 服务 | 身份、KB 配额、幂等与管理 | 重启后同 request_id 返回原结果；慢连接可取消；只读服务正常 |
| P5 迁移 | 中立交换格式、影子验证、切换工具 | 全记录往返、审阅历史、blob 哈希、层级、关系方向逐项对账 |

P0 已交付并通过验收：`sage-db-types`、`sage-db-infer`、`sage-db-reference`。
P0 的 `TermMeta`/`AssertionRecord` 是推理投影，**不是**完整持久记录；完整记录类型属于
P1-2，与投影并存而不替换（见 storage-format §11 的 P1/P2 分工）。

参考求值器使用独立 Rust BTreeMap/集合扫描与小图路径枚举；不复用优化 BFS、
CSR、缓存或任何生产语义函数。两者只共享 types 中的契约类型与排序键：
“两套算法”由 crate 依赖图保证（reference 不依赖 infer），由 CI 的 `cargo tree` 断言。
差分比较的单位是规范化事实行，不含证明字节与执行统计（inference §6.1）。存储正确性
另以“事件序列折叠后的完整记录集”检查，不能让同一求值代码的两个存储后端互相比对
后就宣称语义正确。

## 6. 容量与性能验收

初始基准覆盖 10³ / 10⁴ / 10⁵ 个概念和至多 10⁶ 条活动断言。
它们是测试规模，不是无条件容量承诺。实际准入同时受字节、图大小和快照保留配额约束。

必须测试：真实默认 KB、架构审查夹具、长 depends-on 链、菱形多路径、密 DAG、
多作者同一事实、多代未释放快照、大正文和多模型向量。

记录点查/邻域/闭包/提交的 p50、p95、p99，冷启动、重放吞吐、峰值 RSS、
磁盘写放大与 fsync 次数；注明机器、文件系统、图形态、缓存状态和样本量。
闭包查询必须连同扫描边数报告，不能只按返回行数解释性能。

延迟目标待 P0/P1 基准后固化。旧草案的“10⁵ 断言数十 ms”“所有事实仅 12 MB”
不再作为验收承诺。基础图、证明、正文、向量、旧快照及临时分配必须分别计费。

## 7. 本轮优化后的施工起点

先实现 P0 的记录类型、参考求值器和反例，再做 P1 的事务耐久性。
查询缓存、压缩比优化、增量删除算法都不能成为提交正确性的前置条件。
自研方向已确定；磁盘格式到 P1 故障注入通过后才冻结为 format major 1。
