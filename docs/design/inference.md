# 推理内核与资源边界

> 模型：[data-model.md](data-model.md)；形式语义：[axiomatics.md](axiomatics.md)。

## 1. 计算接口

infer 接收不可变基础图、规则配置与确定性工作预算，返回结果或类型化错误。
无文件/网络 I/O。扫描步数与字节预算由执行器计费；deadline/取消由外层在每个
有界工作块之间检查，不能等一次全量闭包完成才响应取消。

基础图是活动 Assertion 的聚合视图，不是所有可达 Fact 的集合。
读者持有指定版本，查询必须从该版本的基础图或匹配输入摘要的缓存计算。

## 2. 提交前校验，不依赖全量闭包

按以下顺序校验整组操作后的候选状态：

| 检查 | 内容 | 实现边界 |
|---|---|---|
| V1 引用与字段 | ID存在、类型/范围合法、目标修订存在、同库 | 记录索引与事务候选集 |
| V2 自引用 | 所有作者关系禁止 from == target | 活动断言单遍 |
| V3 层向 | 按规则配置检查 layer，不自动改 layer | 基础边单遍 |
| V4 基数 | formal-v1 的 instantiates 每主体最多一个不同目标 | 聚合端点，不能按来源条数算 |
| V5 覆盖 | formal-v1 活动 L3 有实例化目标 | 出度索引 |
| V6 无环 | 每个 acyclic 关系；formal-v1 另查定义边与 depends-on 并集 | 迭代 DFS/Kahn，O(V+E) |
| V7 生命周期 | 退役无活动引用、修订单调、证据/提案基线一致 | 记录与引用索引 |

孤立节点是合法中间状态，只提示。definition_depth 在 DAG 上按拓扑序计算；
legacy-v1 如定义边的混合并集有环，该指标返回 unavailable 并提示，不阻断原有合法数据。
formal-v1 的并集检查失败则不能提交。任何校验超工作预算均拒绝整个事务。

## 3. 求值依赖顺序

1. 聚合活动支撑，生成每个事实的直接注解与来源引用；规范化对称关系的计算键。
2. formal-v1 从直接定义断言生成 R3 的虚拟 depends-on 单跳种子，记录规则来源。
3. 对传递关系做按需单源求值；对称关系只补反向，不做传递。
4. 组合查询与证明输出。所有结果保留 asserted/derived 两种来源信息。

来源标记的统一定义（T4/T5 必须一致实现，不能在各自代码里自行解释）：

| 标记 | 成立条件 |
|---|---|
| `asserted` | **本方向**存在直接作者断言。由 R2 反向得到的读法不算 asserted：作者并未如此声明 |
| `derived` | 存在非循环的规则证明：>=2 跳的 R1、从直接定义断言得到的 R3、或对反向作者断言应用**一次** R2 |
| `disputed` | **所有**有效支撑或路径中存在 contested，而不是只看最强证明 |

`R2(R2(A))` 回到作者方向，不构成第二个来源，因此单独它不得置 `has_derived`。这条与
§3“对称关系只补反向”、§6“不沿对称事实来回追溯”是同一个约束：对称只提供一次方向
补齐，不是新的知识来源。

只有种子阶段完成后，各传递关系的单源查询才可独立执行。
R3 是跨谓词依赖，不能声称整个关系求值过程互不依赖。

## 4. 最宽路径

载体为 bottom + 三档置信度。一条路径取 min，多条路径取 max。
优化实现按 confirmed、hypothetical、contested 三个阈值扫描邻接。
每个阈值运行普通 BFS：第一次能达到目标的最高阈值决定最终注解。
复杂度为 O(3(Vr+Er))，Vr/Er 是实际可达子图的节点与扫描边，非答案行数。

同阈值 BFS 按稳定的 (relation_id, target_id, assertion_id) 顺序访问，选最少跳路径；
相同长度时由固定队列/邻接顺序破平局。禁止依赖 HashMap 遍历顺序。
证明稳定性必须覆盖多个相同强度/长度支撑的情况。

参考实现用有序事实表反复应用 R1–R3：

    candidate = min(left, right)
    if old == bottom or candidate > old:
        facts[key] = candidate
        delta 包含该 key 的插入或注解提升

仅做“三元组集合差”会漏掉已存在事实的注解提升，不能用作 delta 定义。
小图再用路径枚举核对参考实现，避免参考代码与优化代码共享同一个错误。

## 5. 撤回与重算

v1 不实现 DRed 或证明支持计数。撤回更新活动支撑集合、发布新的 graph_digest，
新版本查询按需重算；旧版本与旧缓存仍可被已钉版读者使用。

测试必须覆盖：confirmed 支撑撤回后降到 hypothetical；最后支撑撤回后 absent；
独立直达 Assertion 在其他路径撤回后仍成立；对称方向保持一致。

增量删除是以后优化，需要独立 dependency 索引和与全量参考实现的序列差分。
不能因为 max 幂等就断言所有支持计数算法都不成立；也不能只保存一条证明链，
却声称已知道所有受影响后代。

## 6. 证明格式

每个返回的事实都带一条最强、按上述规则确定的证明根；不承诺枚举所有证明。
一次查询返回多行时，arena 中必须存在与每行对应的根，缺失任何一行即视为生成失败，
不能以“其余行有证明”交付。

    Asserted { assertion_id, revision }
    Symmetry { premise: ProofRef }
    DefinitionImpliesDependency { premise: ProofRef }
    Transitive { left: ProofRef, right: ProofRef }

ProofRef 在响应的有界 proof arena 中寻址；结果信封携带 snapshot_version、rules_digest 与 engine_version（后两者不互换，见 storage §4.3）。
叶子必须回到活动 Assertion 的具体修订；内部节点明确关系、端点和注解运算。
仅有 via: TermId 不能表达对称/R3 的来源，因此不作为完整证明协议。

生成器按种子来源与 BFS 前驱构造无环证明，不沿对称事实来回追溯。
proof_nodes 超限时返回 PROOF_BUDGET_EXCEEDED；不能把不完整证明标成已验证。
历史 proof 可用与否取决于历史快照和记录保留，不由 TermId 永不复用单独保证。

`Transitive { left, right }` 中 `left` 是 `from → mid`、`right` 是 `mid → to`。
方向是语义的一部分：为“规范化”而交换子证明会描述另一种组合。两个求值器可以有
不同的 arena 布局、不同的节点编号，甚至选择不同的（同为最强的）支撑，但都不能
交换已声明方向的子证明。

### 6.1 两个求值器之间的比较契约

参考求值器与优化求值器必须彼此独立：参考实现只依赖共享类型，不调用 infer 的
语义函数、邻接结构或规范化例程来得到“预期值”。可行性由 crate 依赖图保证
（reference 不依赖 infer），由 CI 断言。

差分比较的单位是**规范化事实行**：

| 参与比较 | 不参与比较 |
|---|---|
| 端点 `(from, relation, to)` | proof arena 的节点编号与内部布局 |
| `effectiveConfidence` | elapsed、steps、work_bytes 等执行统计 |
| `asserted` / `derived` 来源标记 | cache Hit/Miss |
| 争议标记与最强支撑的强度 | 行到达顺序（按规范键比较前先排序） |

理由：两个正确实现在这些字段上必须一致，在其余字段上本来就可以不同。把 proof
字节完全相同设为接口正确性条件，会把一个实现细节变成规范，并诱使两者共享构造过程。

证明的正确性单独验证，不通过与另一个实现逐字节比较：

1. **回放核验**：对每个叶子检查该 assertion 修订在声明版本内活动、置信度与其记录
   一致；对每个内部节点按 R1/R2/R3 重算注解，得到根注解，与行的
   `effectiveConfidence` 相等。
2. **最强性**：不存在更强的注解能证明同一事实（在完整求值下与参考实现的注解相等）。
3. **最短性**：在最强注解相同的前提下，跳数不多于参考实现；同长度时按
   `(relation_id, target_id, assertion_id)` 的稳定访问顺序破平局。
4. **平局稳定性**：同一输入重复求值产生同一条证明；打乱输入顺序不改变结果；
   多来源、同强度、同长度的情形必须被显式覆盖。

允许用“断言/规则路径的规范化表达”（例如端点序列 + 规则序列 + 顶层注解）比较平局
结果，这不要求两个求值器共享构造过程；但该表达由测试侧从 arena 独立导出，不能由
被测实现提供。

## 7. 缓存与物化

缓存键至少包含 (kb_uuid, graph_digest, rules_digest, engine_version, relation, source,
query_options)。缓存条目必须是该键下的完整结果；截断结果不写成完整缓存。
命中缓存也需遵守结果字节、行数和取消限制。

v1 仅有按需单源缓存，不做“每次提交全量闭包”或“开库全量闭包”。
提交只构建基础图与校验；缺缓存影响延迟，不影响新快照正确性。
旧任务算完后只能发布到旧 digest 的键，不能覆盖 latest 的条目。
后台预热是同一查询例程、相同预算、低优先级；达到上限即停止，不阻塞提交。

10 万节点的 depends-on 链有 99,999 条直接边，传递闭包为 4,999,950,000 条。
因此断言数与派生数必须分别限制。缓存可按条目淘汰，无需整个快照声称 Fresh/Rebuilt；
结果中的 cache=hit/miss 仅描述执行来源，不能表示知识是否“新鲜”。

## 8. 工作预算与验收

初始配置建议值（实施后据基准调整）：单查询 max_steps=1,000,000、
max_work_rows=200,000、max_work_bytes=32 MiB、max_rows=5,000、max_proof_nodes=20,000。
各值由服务端限制，客户端只能收紧；不能因输入小就跳过检查。

预算不是两个求值器之间的比较维度。参考实现的不动点迭代与优化实现的阈值 BFS 对同一
问题消耗不同步数，因此“同一预算下都成功”不是约定：约定是各自**正确计费**、
**各自**在超限时返回类型化错误。语义比较只在双方都完整完成时进行；资源拒绝由各自
的独立测试验证（差分测试必须跳过任一实现被预算拒绝的用例，而不是要求它通过）。

工作内存按**实际持有**计费，不是按逻辑长度：证明 arena 以
`capacity * size_of::<ProofNode>()` 记账（容量是分配器实际保活的槽位）。序列化字节是
另一个维度，不能与工作内存互相顶替。所有工作区（证明 arena、图索引、查询临时表）**合并**
计入同一个 `max_work_bytes`，不是各自拿一份整个预算；分配用 try_reserve 转成类型化错误，
不用 abort。

共享预算要求每次 push 先检查**当前**占用是否已超上限，再决定是否增长：别的工区变大后，
调用方会把本工区的限额压到已占用之下，此时即使还有 spare capacity 也必须拒绝。

这两个数字必须分开命名，不能互相冒充：

| 数字 | 含义 |
|---|---|
| 已占用（owned/measured） | 各 Vec `capacity()` 之和，按 `size_of` 折算 |
| 准入上界（admitted bound） | 保守估算，分组按 term 数量上界计费，恒 `>=` 已占用 |

只为预算准入保守是对的；但不能把上界报告成“实测内存”。owned 也**不是** OS RSS 或
allocator 元数据：它只数自己拥有的槽位，页粒度、碎片与分配器开销都在其外，不得当作
硬 RSS 上限宣传。

每扫描邻接/规则实例增加 steps；每次分配前申请字节预算。外层每至多 1,024
个步骤调用一次调用方提供的 `QueryControl::checkpoint`；纯推理层不读时钟、不读环境，
deadline 与取消都是调用方注入的策略。检查结果为停止时返回 `Stopped(Cancelled |
DeadlineExceeded)`，绝不返回部分结果。

**不存在“部分成功”的查询结果。** 工作预算、证明预算、取消或 deadline 耗尽都返回
类型化错误，不返回已算出的行。因此 `absent` 只可能来自一次完整求值。`max_rows` 与
`max_output_bytes` 是**输出**限制：只在精确计算与规范排序完成后应用，且截断输出不改变
“该事实是否存在”的结论——被省略的行以 `Limited` 显示标记报告，不与 absent 混淆
（query-dsl §5 区分规范顺序与展示顺序）。

验收同时测稀疏图、密 DAG、长链、菱形、多来源和连续撤回。
必须证明计算在预算内停止，且无全量闭包缓存时仍能提交大但合法的基础图。
