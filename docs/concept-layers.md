# 概念分层体系：L0 到 L3

## 设计意图

分层不是按"重要性"排序，而是按**定义依赖关系**排序。
越低层的概念，越少依赖其他概念；越高层，越依赖下层。

这个结构决定了推理顺序：AI 在推演时必须先加载低层概念，再展开高层概念。

---

## 四个层级的定义

### L0 — 公理（Axioms）

**定义**：无法用系统内其他概念来定义的概念。只能用自然语言直接描述，不能引用系统内其他节点。

**判断标准**：
1. 试图定义它时，只能用自然语言，无法引用系统内其他概念
2. 系统内几乎所有其他概念都直接或间接依赖它
3. 定义在整个知识体系中稳定不变

**特征**：
- 最高抽象度
- 最强稳定性（极少修改）
- 数量最少（一个知识库通常 5-15 个）
- `confidence` 必须为 `confirmed`

**举例（按领域）**：

| 领域 | L0 候选 |
|------|---------|
| 哲学 / 本体论 | 存在、变化、同一性、关系 |
| 产品 / 设计 | 需求、约束、价值、权衡 |
| AI / 认知 | 概念、推理、上下文、激活 |
| 社会 / 组织 | 权力、信任、规则、利益 |

**如何发现 L0**：
先回答"这个知识库是关于什么的"，再问"如果这个概念未定义，其他概念还能被理解吗"——不能，就是 L0 候选。

---

### L1 — 核心概念（Core）

**定义**：使用 L0 概念定义的主干概念，是知识域的主要操作词汇。

**判断标准**：
1. 定义时引用了一个或多个 L0 概念
2. 在该知识域的大多数讨论中都会出现
3. 相对稳定，但随着理解深入可能被精化

**特征**：
- 构成知识库的"主干"
- 数量适中（20-80 个）
- 是大多数查询的激活目标
- 可以有 `hypothetical` 的边，但节点本身应为 `confirmed`

**举例（以"AI 认知"领域为例，L0 为：概念、关系、激活、语境）**：
- 激活策略（依赖：激活、语境）
- 概念图（依赖：概念、关系）
- 上下文预算（依赖：语境、激活）
- 推理路径（依赖：概念、关系、激活）

---

### L2 — 支撑概念（Support）

**定义**：使用 L0 + L1 概念定义的细化概念，为 L1 提供更精确的支撑和补充。

**判断标准**：
1. 定义时同时引用了 L0 和 L1 的概念
2. 不出现在所有讨论中，只在涉及特定 L1 概念时才相关
3. 随理解加深会被增补、拆分或合并

**特征**：
- 作用域比 L1 窄
- 数量较多（可达数百个）
- 常作为 L1 概念的 `part-of` 节点出现
- 可以有 `hypothetical` 置信度

**举例（续上例）**：
- 触发关键词（L1 激活策略的 `part-of`）
- 边类型（L1 概念图的 `part-of`）
- Token 预算分配（L1 上下文预算的 `part-of`）
- 扩散激活半径（L1 推理路径的 `part-of`）

---

### L3 — 具体实例（Instances）

**定义**：某个 L1 或 L2 概念在特定场景下的具体化，是抽象概念的落地形式。

**判断标准**：
1. 是某个抽象概念的 `instantiates` 边的目标
2. 包含具体参数、案例、场景描述
3. 会随实践变化，是最不稳定的层级

**特征**：
- 最具体，最接近现实
- 数量不设上限，按需增加
- `confidence` 可以是 `hypothetical`（待验证的实例）
- 不适合作为其他概念的 `depends-on` 前置（是可替换的实现细节，不是理解前提）

**举例（续上例）**：
- "MANIFEST.md 中每行 ≤ 8 tokens 的 atom 描述规范"（L2 触发关键词的实例）
- "探索模式下 1-hop 邻居全部加载的策略"（L2 扩散激活半径的实例）
- "某次会话的 checkpoint 文件"（L1 上下文预算的实例）

---

## 四层关系总览

```
L0 公理
  └─ L1 核心概念（用 L0 定义）
       └─ L2 支撑概念（用 L0 + L1 定义）
            └─ L3 具体实例（某个 L1/L2 的具体化）
```

**推理方向**：
- 向下（L0 → L3）：演绎，从抽象到具体，用于生成推演
- 向上（L3 → L0）：归纳，从案例到原则，用于概念发现

**激活顺序**：AI 在处理任何问题时，应先确认 L0 已加载，再展开 L1，最后按需加载 L2/L3。

---

## 常见误判

| 误判 | 原因 | 纠正方式 |
|------|------|---------|
| 把"重要的概念"放 L0 | 混淆重要性和基础性 | 问"它能被系统内其他概念定义吗" |
| L0 概念太多（>20个） | 没有真正做分解 | 检查是否有 L0 可以被其他 L0 定义 |
| L3 概念放到 L1 | 把具体案例当核心词汇 | 问"这个概念在大多数讨论中都会出现吗" |
| 所有概念都在 L2 | 没有做层级区分 | 从 L0 开始，自上而下分配 |
